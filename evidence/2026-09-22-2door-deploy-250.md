Goal (owner): deploy the whole system to `194.163.187.250`; Nansen queries must egress from
**two** IPs — 250 and 228 — so the pool cap becomes `2 × CRAWL_DOOR_CAP_PER_MIN(40) = 80`/min.
Approach: Plan A — **zero code change**; 250 gets a local tinyproxy so its own IP is representable
as a proxy line, and `data/proxies-server.txt` carries 2 lines = 2 doors.

## Effective budget

`2 doors × 40 = 80 req/min` (sliding 60 s window, per door; per path `2 × 30 = 60`). No env change:
`CRAWL_DOOR_CAP_PER_MIN` stays 40. `doorCapPerMin` is a **sliding-window cap, not a pacer** — the 80/min
is emitted in bursts and CF has challenged bursts before; a pacer (~1.5 s/request/door) is the follow-up
if bursts start getting 403.

## Rollback

1. remove the `CRAWL_PROXY_FILE=...` line from `/root/signal_scan/server/.env` (or restore `.env.bak.20260922T181518`) → single direct door (IP 250); or
2. drop line 1 of `data/proxies-server.txt` → single 228 door;
then `make restart`. No DB/schema touched; `getPool()` reads the file once at boot → restart is the reload.
