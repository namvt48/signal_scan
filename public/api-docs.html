Public API · v1 · read-only

Market data, one request at a time.

Quick start

HTTPS · JSON · GET

No account, API key, or Authorization header is needed. Do not send dashboard login credentials to these routes. The status call proves the public process answers; it does not prove stored data is available.

curl -sS 'https://signal-scan.duckdns.org/api/v1/status'
# {"status":"ok","version":"v1"}

curl -sS 'https://signal-scan.duckdns.org/api/v1/tokens?limit=10&offset=0'
Stored data only. Responses reflect what Signal Scan currently retains. Expired or pruned source history is not reconstructed, and REST cursors report gap: true when rows were pruned.

WS/wsLive tracker-buy inflow stream

Connect to wss://signal-scan.duckdns.org/api/v1/ws. No API key or header. The stream is server-to-client only; the server closes connections that send messages with code 1008.

The FOMO instance exposes wss://signal-scan.duckdns.org/api/v1/fomo/ws with the same protocol and filters. Catch up with GET /fomo/alerts?after_id=. Both paths share the 64-connection limit but poll their own upstream; an unavailable upstream closes only its stream with code 1011.

MessageFieldsMeaning
ready{type:"ready", afterId}Sent once after setup. afterId is the latest stored alert ID at connection time.
inflow{type:"inflow", data:<alert>}Sent for each newly stored trackerBuy alert, using the same alert schema as REST.

Delivery rules

BehaviorDetail
No replayOnly alerts stored after the connection are streamed. Catch up with GET /alerts?after_id=.
ScopetrackerBuy only. fresh, t100, and sells are never streamed.
Stored firstAn inflow is sent only after the alert is stored; deduplicated duplicate trades produce no event.
Not exactly-onceDeduplicate by data.id and advance your cursor only after processing succeeds.
HeartbeatPing about every 25 s; clients that miss pong are removed. Proxy read-idle timeout is 75 s.
Capacity64 concurrent connections per process; excess handshakes receive HTTP 503. Alerts are polled once per process and shared.
BackpressureSlow consumers may be closed so one client cannot exhaust process memory.
const ws = new WebSocket('wss://signal-scan.duckdns.org/api/v1/ws');

ws.addEventListener('message', ({ data }) => {
  const message = JSON.parse(data);
  if (message.type === 'ready') console.log('cursor', message.afterId);
  if (message.type === 'inflow') console.log('inflow', message.data); // dedupe by data.id
});

ws.addEventListener('close', (event) => console.log('closed', event.code, event.reason));

Server-side consumer: reconnect + REST catch-up

Node 20+ reference consumer from the user guide. It uses the ws package plus Node's built-in fetch (npm install ws). A single promise queue serializes messages, so catch-up and live inflows never interleave and the cursor only advances after processing succeeds.

import { WebSocket } from 'ws';

const API = 'https://signal-scan.duckdns.org/api/v1';
const WS_URL = `${API.replace('https:', 'wss:')}/ws`;
let lastProcessedId = null; // Replace with durable storage if restart recovery is required.
let queue = Promise.resolve();
let retryDelayMs = 1000;

async function catchUp(afterId, throughId) {
  let cursor = afterId;
  while (cursor < throughId) {
    const url = new URL(`${API}/alerts`);
    url.searchParams.set('after_id', String(cursor));
    url.searchParams.set('limit', '100');

    const response = await fetch(url);
    if (!response.ok) throw new Error(`Alert catch-up failed: HTTP ${response.status}`);
    const page = await response.json();
    if (page.gap) console.warn('Alert history gap: older rows have been pruned.');

    for (const alert of page.data) {
      if (alert.id > throughId) break;
      if (alert.metric === 'trackerBuy') await handleInflow(alert);
      // Advance past every alert type; REST returns more than inflow events.
      lastProcessedId = alert.id;
    }

    if (page.nextId <= cursor) break;
    cursor = Math.min(page.nextId, throughId);
    lastProcessedId = Math.max(lastProcessedId, cursor);
  }
}

function connect() {
  const ws = new WebSocket(WS_URL);
  ws.on('message', (raw) => {
    queue = queue.then(async () => {
      const message = JSON.parse(raw.toString());
      if (message.type === 'ready') {
        if (lastProcessedId === null) {
          // First connection: start live at the server-provided cursor, no history replay.
          lastProcessedId = message.afterId;
        } else {
          // Reconnect: recover stored inflows up to the new connection's ready cursor.
          await catchUp(lastProcessedId, message.afterId);
        }
        return;
      }

      if (message.type === 'inflow' && message.data.id > lastProcessedId) {
        await handleInflow(message.data);
        lastProcessedId = message.data.id;
      }
    }).catch((error) => console.error('Signal Scan consumer error:', error));
  });

  ws.on('open', () => { retryDelayMs = 1000; });
  ws.on('close', () => {
    setTimeout(connect, retryDelayMs);
    retryDelayMs = Math.min(retryDelayMs * 2, 30000);
  });
  ws.on('error', (error) => console.error('Signal Scan WebSocket error:', error.message));
}

async function handleInflow(alert) {
  // Replace with application logic. Persist/commit by alert.id for idempotency.
  console.log(alert.chain, alert.ca, alert.value, alert.id);
}

connect();

This example keeps its cursor in memory; persist lastProcessedId durably if the consumer must recover after a process restart. If a fetch or handler throws, the queue rejects, the cursor stops advancing, and the error surfaces — define your own retry/durable-commit policy for production.

Browser pages on another origin can open the WebSocket, but cannot run REST catch-up directly because CORS is disabled — perform catch-up in your backend.

HTTP quota

120 requests/minute per process, shared by all callers. At most 16 concurrent requests; excess receives 503. Identical in-flight export requests share work and successful exports are cached for 500 ms in a bounded cache.

WebSocket capacity

64 connections per process, independent of the HTTP quota. The stream is polled once per process and shared across clients.

Quotas and caches are process-local, so the service runs one public replica. Do not assume limits scale with replicas.

Data exposure
