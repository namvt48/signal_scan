Feature milestones

2026-10-20API foundationCommit 7f6d758

Introduced the standalone public API

Added the separately operated public API service and its consumer guide. The initial implementation established an external read-only surface while keeping dashboard exports behind a private service credential.

  • Documented the public API base URL and unauthenticated access model.
  • Added a standalone service lifecycle and routing through the HTTPS host.
  • Kept the dashboard login and private export endpoint separate from public callers.
2026-10-22API expansionCommit 14d1758

Expanded token data and holder analytics

Updated the API routes, export DTOs, contract tests, and consumer docs to expose additional stored analytics without exposing dashboard write operations.

  • Added token distribution detail and top-100 holder data.
  • Added cached top-100 balance-chart windows: day, week, and month.
  • Expanded token/alert response fields, including tracked-wallet aggregates and public token metadata.
  • Documented the supported data boundaries, missing-value behavior, and privacy implications.
2026-10-23API expansion

Added FOMO dashboard data

Extended the public API with a second private export upstream so the FOMO dashboard instance can be read without exposing its write routes.

  • Added the FOMO token table (token payload plus per-token fomoUsers) and single-token lookup.
  • Added FOMO watch-list, per-token FOMO user stats, per-user trades, and positions/holdings routes.
  • Added FOMO-instance alerts, wallets, wallet trades, and a dedicated /api/v1/fomo/ws tracker-buy stream.
  • Positions now include refresh freshness (complete, truncated, available, checked/captured times).
  • Kept non-FOMO token, alert, and wallet data on the existing instance-A upstream.
  • Documented that FOMO tokens, identities, alerts, wallets, trades, positions, and holdings are public to every caller.
  • FOMO routes return 502 when the second upstream is not configured.

Contract boundaries

What stays private

Public surface

Read-only data only. No caller authentication, no dashboard login, and no write endpoints. Token, alert, and wallet data come from instance A; FOMO tokens, alerts, wallets, and watch-list data come from instance B through a second private export upstream.

Private service boundary

The public service uses a backend-only export credential to fetch data. That credential is not part of the public contract and must never be placed in this page or consumer requests.
